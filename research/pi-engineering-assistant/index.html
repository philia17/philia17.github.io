Engineering Assistant

The question

A small language model can produce a fluent answer without showing whether it found the relevant material or performed the calculation correctly. This project explores a Raspberry Pi 5-targeted engineering assistant that makes those paths visible.

A four-bit Qwen3-1.7B model is paired with course-material retrieval and deterministic calculation tools. In Ask, an answer can be inspected alongside its sources and calculation trace. In Quiz, feedback and supporting sources appear after the answer is submitted.

My contribution

I led implementation of the edge prototype, integrated retrieval and deterministic calculation tools, built the inspectable Ask/Quiz workflow, and compared system configurations within the team project.

What was measured

Offline GPU reference0.777 / 1.000

Mean rubric score for Base+Tools: tool-augmented RAG. Seven configurations compared on 96 EEE questions.

Separate Pi 5 CPU run0.498 / 1.000

Mean rubric score for closed-book Base on the same 96 questions, without retrieval, tools or web processing.

These are rubric scores, not accuracy percentages. The evaluation used AI-assisted rubric scoring and author review, rather than independent non-author validation. The GPU comparison, Pi device observations and selected web demonstrations are separate evidence layers. The offline retrieval comparison does not validate end-to-end web quality.

For supported numerical items, the deterministic Calculator executes the calculation directly. A displayed source or trace helps inspection but does not itself establish that an answer is correct.

Explore the source

The public repository includes generic offline calculator examples, retrieval and application source, and checks that can run without a model or Pi. It omits private teaching material, restricted benchmark packets, model weights and deployment configuration. Full model-backed Ask/Quiz use requires an authorised local corpus, built indexes and a compatible model runtime.
