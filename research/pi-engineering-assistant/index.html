Project overview

A compact language model can give a fluent answer while using the wrong material or making an arithmetic error. This prototype pairs a four-bit Qwen3-1.7B model with course-material retrieval and deterministic calculation tools.

Ask shows an answer alongside its sources or calculation trace. Quiz reveals feedback and supporting sources after an answer is submitted. The platform targets a Raspberry Pi 5; the reported evaluation separates its components and devices.

My contribution

I led implementation of the edge prototype, integrated retrieval and calculation tools, built the inspectable Ask/Quiz workflow, and compared system configurations within the team project.

Results and scope

The main evaluation compared seven configurations on 96 EEE questions using an offline GPU reference. The table reports mean rubric scores on a 0–1 scale and the number of answers meeting the study’s fully-correct criterion.

RAG means retrieval-augmented generation; SFT means supervised fine-tuning. Rubric scores are not accuracy percentages. Base + Tools is the tool-augmented RAG configuration: supported calculations use the deterministic Calculator; other requests use retrieval. The highlighted GPU Base + Tools and Pi closed-book Base results test different configurations and must not be read as a matched hardware comparison.

A separate matched closed-book Base comparison used the same quantised model artefact and 96 questions on both devices: GPU mean 0.503; Pi mean 0.498. The mean difference (Pi − GPU) was −0.005, with a 95% interval from −0.041 to +0.032. The study did not establish equal answer quality.

On a separate 24-question retrieval-sensitive set, Base+RAG scored 0.779 versus 0.325 for closed-book Base (a +0.454 mean change). The Holm-adjusted test for fully-correct outcomes was p = 0.0625, which did not meet the 0.05 threshold. On 24 pre-classified calculator-supported questions, Base+Tools scored +1.000 mean over Base+RAG. Neither tested SFT recipe exceeded its matched Base configuration.

The evaluation used AI-assisted rubric scoring followed by author review, not independent blinded validation. Device observations and selected web demonstrations are separate evidence layers. The study did not test learning benefits, usability or end-to-end web reliability. A displayed source or trace helps inspection but does not itself establish that an answer is correct.

Paper abstract

Generic language-model assistants do not naturally align with a particular course. We present a Raspberry Pi 5-targeted platform combining a compact Qwen3-1.7B model, course-grounded retrieval, deterministic calculation, and a Web portal that exposes answers, evidence, and tool execution. It is configurable for individual course requirements; we evaluate system quality and edge deployment, not learning outcomes. GPU-accelerated evaluation compares seven configurations over 96 course questions: closed-book generation, retrieval-augmented generation (RAG), Calculator execution, and two supervised fine-tuning (SFT) recipes. A separate 24-question set compares Base and Base+RAG approaches. Base + Tool-Augmented RAG achieved the highest mean rubric score of 0.777 on a 0–1 scale. Retrieval improved mean source-sensitive quality; deterministic Calculator execution gave the clearest gain on 24 preclassified supported items. Neither SFT recipe demonstrated improvement over its matched Base configuration. A paired 96-question Base comparison did not detect a directional GPU–Pi score difference; the Pi ran the same quantized artifact more slowly.
