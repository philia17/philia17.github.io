項目概覽

小型語言模型可能流暢作答，卻引用錯誤資料或算錯數字。此原型將四位元 Qwen3-1.7B 模型與課程資料檢索及確定性計算工具結合。

Ask 在答案旁呈現來源或計算過程。Quiz 在提交答案後顯示回饋及支持資料。平台以 Raspberry Pi 5 為目標裝置；報告中的評估分別呈現不同元件與裝置的結果。

我的貢獻

我在團隊項目中主導邊緣原型的實作，整合檢索與計算工具，建立可檢視依據的 Ask／Quiz 流程，並比較各種系統配置。

結果與適用範圍

主要評估在離線 GPU 參考環境下，以 96 道電機與電子工程題目比較七種配置。表格列出 0–1 評分規準的平均分數，以及符合研究完全正確標準的答案數。

RAG 指檢索增強生成；SFT 指監督式微調。評分規準分數並非準確率百分比。Base + Tools 是加入工具的 RAG 配置：支援的計算交由確定性 Calculator 執行，其他請求使用檢索。特別列出的 GPU Base + Tools 與 Pi 閉卷 Base 測試不同配置，不能視為配對硬體比較。

另一組配對閉卷 Base 比較在兩種裝置上使用相同的量化模型檔案與 96 道題目：GPU 平均分數為 0.503，Pi 為 0.498。平均差值（Pi − GPU）為 −0.005，95% 區間為 −0.041 至 +0.032。研究並未確立兩者答案品質相同。

在另一組對檢索敏感的 24 道題目中，Base+RAG 得分 0.779，閉卷 Base 為 0.325（平均增加 +0.454）。完全正確結果的 Holm 校正檢定為 p = 0.0625，未達 0.05 門檻。在預先分類為計算器支援的 24 道題目中，Base+Tools 的平均分數比 Base+RAG 高 +1.000。兩種受測 SFT 方法均未超越對應的 Base 配置。

評估採用 AI 輔助的規準評分，再由作者審閱，並非獨立盲測驗證。裝置觀察與選定的網頁示範屬於不同層次的證據。研究未測試學習成效、易用性或端到端網頁可靠性。顯示來源或計算過程有助檢視，但本身不能證明答案正確。

論文摘要

通用語言模型助手未必能自然契合特定課程。我們提出一個以 Raspberry Pi 5 為目標裝置的平台，結合小型 Qwen3-1.7B 模型、以課程資料為依據的檢索、確定性計算，以及呈現答案、證據和工具執行情況的網頁介面。平台可依個別課程需求設定；本研究評估系統品質與邊緣部署，而非學習成效。GPU 加速評估以 96 道課程題目比較七種配置，涵蓋閉卷生成、檢索增強生成（RAG）、Calculator 執行與兩種監督式微調（SFT）方法。另以 24 道題目比較 Base 與 Base+RAG。Base + Tool-Augmented RAG 在 0–1 評分規準中取得最高平均分數 0.777。檢索提升了對來源敏感題目的平均作答品質；確定性 Calculator 執行在預先分類為支援的 24 題中帶來最明顯的增益。兩種 SFT 方法均未顯示優於對應 Base 配置的改善。96 題配對 Base 比較未檢出具方向性的 GPU–Pi 分數差異；Pi 執行相同量化模型檔案時較慢。
